Hswen Lab · May 2026 – Present

AI Many-Analysts Study: Do LLM Agents Agree on the Same Wearable Health Data?

RoleUndergraduate Researcher · study proposer and design lead
DataNIH All of Us Controlled Tier · Fitbit sleep, activity, heart rate linked to EHR
StatusProposal stage · Sep 2026 – Present

Overview

Reasonable preprocessing and modeling choices can lead analysts to different conclusions from the same data — the classic many-analysts result, where 70 teams tested the same hypotheses on the same dataset and disagreed. Wearable data has no standard cleaning pipeline, which makes the problem worse. I proposed asking the same question of AI: given one health question and one dataset, do independent LLM agents reproduce human analytic variability, or collapse onto defaults that hide uncertainty?

Study Design

  • Many independent LLM agents receive a shared question (for example sleep versus memory, or steps versus blood pressure) and each chooses its own valid-wear-day rules, sleep measures, covariates, and statistical models.
  • Their effect-estimate dispersion is compared against a human-specified multiverse / specification-curve analysis, so disagreement can be traced back to specific analytic choices.
  • Open-weight models will run on GPU apps inside the secure workspace, since participant data cannot leave it under the data use agreement.

What I've Built So Far

  • Designed the study and presented the proposal to the research group.
  • Configured the All of Us Researcher Workbench environment on Google Cloud: JupyterLab, the Controlled Tier BigQuery dataset reference, and workspace storage.
  • Set up GitHub-over-SSH version control with a data-file .gitignore and nbstripout so notebook outputs never reach a commit.
  • Wrote the Python / BigQuery setup and query code, then diagnosed a query blocker as a VPC Service Controls network-perimeter policy rather than account permissions and documented it for platform support.

MACHAMP Lab · Jan 2026 – Present

Scalar-on-Tensor Regression with Unbalanced Tensor Predictors

AwardExcellence in Research · UMD Undergraduate Research Day
RoleUndergraduate Researcher
MethodsTensor regression, group lasso, clustering, simulation studies
StatusManuscript in preparation · Cell Painting extension

Overview

I developed TEPIG (TEnsor sparse grouP lasso with clusterInG), a method that predicts kidney function one year after transplant from 43 pathomic features across multi-slide biopsies, under the guidance of Professor Jeremy Rubin. The work won the Excellence in Research Award among 550+ participants at UMD's Undergraduate Research Day and was presented at the AIM Symposium in May 2026.

TEPIG extends CLUSSO from matrices to tensors: it imposes feature-level group sparsity across a clusters × features × sections tensor without the low-rank constraint prior tensor methods require, so each patient's variable number of tissue structures can be modeled while the selected features stay interpretable.

Methods and Evaluation

  • End-to-end Python pipeline: Gaussian-mixture clustering of tubule-level features, weighted cluster-mean tensors, a group lasso solved with FISTA, λ chosen by 5-fold cross-validation, and an adaptive universal threshold as post-fit pruning.
  • Validated across 200-repetition simulations in 70 settings on SLURM-managed HPC: adaptive thresholding cut TEPIG's mean false-positive rate from 0.156 to about 0.0001, substantially below both CLUSSO and naive lasso across all settings.
  • On a kidney-transplant cohort, matched CLUSSO's test error while selecting three biologically interpretable features.
  • Now extending TEPIG to the Cell Painting Gallery (~30K compounds, U2OS cells) to predict L1000 gene-expression outcomes — real-data results are in hand and a manuscript is in preparation, with a ~400-plate run planned on UMD's Zaratan cluster.
Python NumPy scikit-learn SLURM HPC

Independent ML Research · 2024 – 2025

Forecasting Soccer Player Value via Integration of Injury History with Machine Learning

GitHub ↗ Research Paper ↗
TypeIndependent ML research
DatasetRoughly 17K player-seasons
Best ModelR² 0.856 · MAE ~$3.82M

Overview

I built a time-aware machine learning pipeline to forecast soccer player transfer value by integrating multi-year injury history, season context, and more than 300 engineered features across roughly 17K player-seasons.

The modeling setup uses 1- to 5-year sliding windows so each horizon evaluates how well value can be predicted as a player's career evolves, rather than assuming seasons are independent. The four-year window performed best.

Modeling Approach

  • Engineered 300+ features from player stats, multi-year injury history, and season context scraped from Transfermarkt, across roughly 17K player-seasons.
  • Trained XGBoost models over 1–5-year sliding windows, with a separate injury-duration model tested as an intermediate signal — the four-year value model reached R² 0.856 with MAE ≈ $3.82M on an 80/20 split.
  • Key finding: prior market value dominates valuation by a large margin, and public injury history adds little predictive power — a negative result I report honestly.
  • Authored a 20-page research paper documenting the feature engineering, window construction, and model comparisons.
